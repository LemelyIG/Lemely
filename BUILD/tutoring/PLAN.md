### 0.3 One shared worktree (the only mode)
Subagent Bash is pinned to the lead session's current worktree (memory `subagents-inherit-session-worktree`), so per-task worktrees are not used: lead-created sibling worktrees refuse Bash, and harness `isolation: "worktree"` checkouts have no `.venv` or `web/node_modules`. Every lane works in WT. The mode is sound because of four rules, each enforced by a step in §0.5:

1. **Disjoint ownership.** Lanes in one wave own disjoint files; the dispatch brief of each lane names its owned files and the files the other live lanes own (memory `parallelize-independent-work`).
2. **No lane edits a hot file, even uncommitted.** Route tasks mount their own routers in tests through `tests/tutoring_app.py::app_with_routers(...)` (T00), so nobody needs `lemely/web/app.py` or `tests/test_authz_matrix_complete.py` mid-wave; those changes travel as `HOT PATCH` text (§0.4).
3. **Evidence never comes from the shared tree.** A lane's static checks, acceptance tests, scan suites and mutation proofs run on a **candidate export**: a path-limited `git archive` of `HEAD` overlaid with exactly the lane's own changed files (§0.5 step 5). Runs in WT are fast feedback only, because they can see other lanes' unfinished edits (memory `parallel-agents-need-commit-paths`).
4. **Explicit-path commits, no history rewriting.** `git commit -S -- <own paths>` records only those paths even when another lane has staged files; no `--amend`, `stash` or `reset`. Rollback is per lane commit range (§5.3), not per merge.

### 0.4 Hot-file rule
A task never edits a hot file (§3), committed or not. It returns the change as a unified diff in its return contract (`HOT PATCH`). The lead applies every hot patch in the wave's integration row, after every lane of the wave has committed and the tree is quiescent. After a wave integrates, every file its tasks owned becomes hot (lead) unless a later card names it as owned; fix tasks at W8/IF get explicit, one-owner-per-file ownership from the lead (P19).

### 0.5 Lane protocol (every task)
- [ ] **1. Read** the task card, its SPEC sections, its `Consumes` interfaces at the current `HEAD` (`git show HEAD:<path>` or Read), and `BUILD/tutoring/handoffs/` for the tasks it depends on. Run `df -h /` once; below 10 GiB free, stop and report.
- [ ] **2. Red:** write the test files listed under *Tests first* (own files only). Run them in WT with `bash scripts/tutoring/pytest.sh <own new test files>` (or `npm --prefix web test -- <files>`) for fast feedback. Record one `RED` line per new test file (§0.8): the first failing assertion for the missing behaviour, or `n/a (absence)` / `n/a (regression guard)` plus the mutation that will prove it.
- [ ] **3. Green:** implement the minimum in the owned files.
- [ ] **4. Pre-commit (own files, before any commit):** `bash scripts/tutoring/precommit.sh --files <own changed paths>`, then `git status --short -- <own paths>`. An autofix is a finding: read the diff, keep it, and say so in `NOTES` (memory `precommit-fix-hides-ci-failures`). The wrapper skips the three whole-package hooks (`mypy`, `pyright`, `import-linter`) here, because in WT they would judge other lanes' unfinished files; step 6 runs them on the exact candidate.
- [ ] **5. Candidate export:** `bash scripts/tutoring/export.sh <ID>-c<n> HEAD --overlay <own changed paths>` (add `--web` for any web file; add `--delete <paths>` for deletions). It prints the export root `<T>` = `.omc/exports/<ID>-c<n>` (gitignored, on disk). `n` starts at 1 and grows with each fix round.
- [ ] **6. Evidence on the candidate (from WT, targeting `<T>`):**
  - Python lanes: `bash <T>/scripts/tutoring/static.sh` (ruff check, ruff format check, mypy, pyright with this tree's `extraPaths`, lint-imports, review-rate gate; memory `shared-venv-editable-pth` for why pyright needs the override, P17); the card's acceptance pytest command; `bash <T>/scripts/tutoring/scan_py.sh`; and the `AFFECTED` list the lead put in the brief: `bash <T>/scripts/tutoring/pytest.sh <that list>`.
  - Web lanes: the card's vitest files `npm --prefix <T>/web test -- <files>`, then `npm --prefix <T>/web run typecheck`, `npm --prefix <T>/web run lint`, `npm --prefix <T>/web run check:copy`, and SCAN-WEB `npm --prefix <T>/web test` (the whole node-only unit suite; 94 of its 204 files scan `src/`).
  - Mutation proofs (§0.8): edit the guarded file **inside `<T>`** with the Edit tool, rerun the named test through `<T>`'s wrapper, record that it goes red, restore with `cp <own WT path> <T>/<same path>`, rerun green.
  - Every pytest summary must show `0 skipped` (§0.8).
- [ ] **7. Commit:** `git add -- <own new paths>`; `git commit -S -m "<type>(tutoring): <summary>" -- <own paths>`; `git log -1 --format=%H -- <first owned path>` gives the lane's SHA; `git diff --exit-code <SHA> -- <own paths>` must exit 0 (the commit equals the candidate for the lane's paths).
- [ ] **8. Clean up:** `rm -r .omc/exports/<ID>-c<n>` for every candidate (`rm -rf` is denied by this session's permissions; `rm -r` is verified).
- [ ] **9. Return** the contract (§0.6).

Any red in step 6 → fix in WT → new candidate (`c<n+1>`) → step 6 again. Step 7 never happens on a red candidate. A lane never runs `pre-commit run --all-files`, Alembic against the gate database, or a live-stack command.

### 0.8 Evidence rules (P11, P21)
- **RED.** A behaviour test records its first failing assertion before code. A test that cannot fail before code (absence, negative scans, "writes no audit row", "no-store", "no key outside DTO", regression guards that pass today) records `RED: n/a (absence)` or `n/a (regression guard)` and **must** have a `MUTATION` line instead. An ImportError is never a RED.
- **Non-vacuity.** Every scan or enumeration test asserts its own coverage: an exact or minimum count of what it scanned (e.g. "classes discovered == SPEC §b.3 names", "routes enumerated == 70", "SCAN-PY files ≥ 10"), and that count appears in `NONVACUITY`.
- **No self-comparison.** A test may not compare an artefact with a literal the same lane wrote from the same source; derive the expected side from SPEC text (parsed) or from an independent function.
- **Skips.** With the local stack up, every named-file pytest summary shows `0 skipped`. The only exceptions are test ids listed in `BUILD/tutoring/handoffs/I0-baseline.md` (skips recorded at I0b for files that need a key or GoTrue, by full test id). Anything else skipped is a red.
- **Mutation proofs** run only inside an export; never in WT, never on a file another lane owns (memory `temporary-file-access-is-still-ownership`).

### 5.3 Rollback and stop plan
- **A task fails its acceptance twice** (two full implementer attempts, each followed by a reviewer verdict): escalate one tier and re-dispatch fresh with both failure reports (C → B → A).
- **A Tier A task fails twice:** one more attempt at effort `max`. If that fails: **STOP** the task and every task depending on it (§1.2 edges); finish independent tasks in the wave; record `BLOCKED` with the failure evidence in `BUILD/tutoring/handoffs/blocked.md`; ask the user.
- **An integration gate goes red (local or CI):** do not patch on top. Find the lane by re-running the red test on exports that each drop one lane's commits (`bash scripts/tutoring/export.sh I<n>-bisect-<ID> HEAD --overlay …` built from `tutoring/pre-W<n>` plus the other lanes' files), then revert that lane's commits on the feature branch with `git log --format=%H tutoring/pre-W<n>..HEAD -- <lane's owned paths>` and `git revert -S --no-edit <sha>` per commit, newest first (paths are disjoint, so this touches no other lane); revert the hot-patch commit separately if it is the cause. Return the task to its owner with the failing output. `git reset --hard tutoring/pre-I<n>` only with the user's approval, and never after a push (it would need a force-push).
- **A spec gap or contradiction** found by a task: the task returns `BLOCKED` with the exact SPEC section; the lead decides or asks the user, edits SPEC/DECISIONS, and re-dispatches. No implementer edits SPEC.
- **A hot-file patch conflicts** with another task's patch: the lead resolves by hand and re-runs that wave's gate.
- **Agent failure notice** (API timeout): check `git status --short` and `git log --oneline -5 -- <the lane's paths>` before re-dispatching (memory `agent-failure-notice-is-not-death`); an uncommitted partial lane is resumed by a fresh agent on the same owned files.
- **Disk:** `df -h /` before each wave and in every `export.sh`; below 10 GiB free, no new export starts; the lead lists `.omc/exports/` and removes stale exports with `rm -r`.

### 5.4 Shared-database hygiene
Covered by §0.9: the shared `postgres` database stays at develop's head in `dedicated` mode, and in `shared` mode every live run ends with a verified downgrade to the recorded revision. Gate migrations use `lemely_tutoring_gate`. The lead never drops a database it did not create.
